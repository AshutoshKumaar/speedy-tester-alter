# SpeedyType SEO Audit

Audit date: 2026-11-17 (client timezone). Scope: complete checked-out repository source review plus owner-provided historical GSC observations. No live Search Console property, production crawl, deployment settings, or performance field data was available. No application code was changed.

## Executive assessment

The code has a sound baseline: the preferred `https://www.speedytypeapp.com` origin is used in metadata base, sitemap and robots; static pages generally define unique metadata/canonicals; article content is server-rendered from a single source; sitemap dynamically includes article slugs; and useful internal links connect tools and guides. Highest-confidence fixes are accurate sitemap modification dates, an explicit indexability decision for local utility pages, output validation for canonical/metadata/statuses, and validating the three reported article URLs for discoverability/content value. No P0 defect is confirmed from source alone. The HTTP/HTTPS and host redirect report remains an important production check, not evidence of a current misconfiguration.

## Technical SEO findings

### P1 — Static sitemap dates required reliable route-level values — fixed in source

- **Evidence before fix:** `src/app/sitemap.js` assigned `lastModified: now` generated by `new Date().toISOString()` to every static route, regardless of content change. The 13 article entries used `updatedAt || publishedAt`.
- **Affected:** all 16 static sitemap URLs.
- **Why it matters:** `lastmod` should indicate a meaningful page modification. Artificially fresh dates reduce signal quality and do not reflect actual updates; sitemap dates do not force crawling or ranking.
- **Files:** `src/app/sitemap.js` and ideally route/content source timestamps.
- **Implemented:** static route dates now match the latest meaningful route-source changes recorded in Git history: 2026-09-24, 2026-09-26, or 2026-10-18, as applicable. Article `updatedAt` / fallback `publishedAt` is retained when valid and not in the future; invalid/future values are omitted. WWW host is unchanged. For any future route without a dependable date, omit `lastModified`.
- **Complexity:** low–medium.
- **Verification:** local production build output contains 29 unique WWW URLs with route-specific static dates and article dates no later than 2026-10-18. Live `/sitemap.xml` still returns the pre-deployment version, with static dates all `2026-10-18`; all 29 live URLs returned HTTP 200. Deployment is intentionally not performed.

### P1 — Utility pages are included in the indexable sitemap without a documented policy

- **Evidence:** sitemap includes `/scores`, `/themes`, `/settings`, plus all legal/contact pages. Scores and settings are browser-local features; themes is largely a tool/gallery. These routes have metadata and are not noindexed in source.
- **Affected URLs:** `/scores`, `/settings`, `/themes`; review `/contact`, `/privacy-policy`, `/terms`, `/disclaimer` too.
- **Why it matters:** sitemap inclusion asserts desired indexing, while local/session utility pages may provide little standalone search value. Google may crawl and choose not to index; this is a product/indexation decision, not necessarily a defect.
- **Files:** `src/app/sitemap.js`, relevant route metadata files.
- **Fix:** assess each route’s independent search utility and intended audience; keep only useful canonical index candidates in sitemap. Apply `noindex` only when intentionally excluded, never block it in robots if Google must read the directive.
- **Complexity:** low.
- **Verification:** inspect rendered robots meta and sitemap; monitor URL Inspection and Page Indexing after recrawl.

### P1 — WWW/HTTPS redirect behavior is not evidenced by source

- **Evidence:** metadata, sitemap, robots and content links use `https://www.speedytypeapp.com`; `next.config.mjs` has no redirects. Hosting/DNS redirect rules are outside the checked-out source. Owner reports historical alternate HTTP/HTTPS and WWW/non-WWW URLs under Page with redirect.
- **Affected:** HTTP homepage, HTTPS non-WWW homepage, and any corresponding alternate paths.
- **Why it matters:** consistent permanent redirects consolidate signals and avoid duplicate crawl paths. Existing GSC “Page with redirect” can also be normal if alternates redirect correctly.
- **Files/config:** Vercel project/domain settings, DNS/CDN rules; keep WWW host in `src/app/layout.js`, `sitemap.js`, `robots.js`.
- **Fix:** no code migration proposed. Verify each protocol/host directly and retain the approved WWW destination. Establish single-hop permanent redirects to HTTPS WWW.
- **Complexity:** low if configuration is already correct; medium if redirect rules need repair.
- **Verification:** request each host/protocol with `curl -I`, check one 301/308 hop to the matching HTTPS WWW URL, then inspect canonical and GSC Page with redirect samples.

### P2 — Validate metadata output and global canonical inheritance

- **Evidence:** `layout.js` defines canonical `/`; most route pages define canonicals, and practice uses a route layout. Blog detail uses generated metadata. Source inspection is not a substitute for rendered HTML validation. Root title template is `%s`, and page titles use mixed brand suffix conventions.
- **Affected:** all indexable routes; highest priority `/`, `/typing-practice`, `/blog/[slug]`.
- **Why it matters:** verify each response has one correct absolute canonical, distinct title/description, expected robots, OG/Twitter values, and no inherited root canonical on child routes.
- **Files:** `src/app/layout.js`, all `page.js` metadata, `typing-practice/layout.js`, `blog/[slug]/page.js`.
- **Fix:** after capturing output, correct only proven inheritance/duplication/brand issues. Do not globally rewrite titles without query/CTR evidence.
- **Complexity:** medium.
- **Verification:** fetch server HTML for representative routes and inspect `<title>`, description, canonical, robots, OG and Twitter tags; test unknown article slug returns HTTP 404.

### P2 — Owner-reported “Discovered – currently not indexed” pages need URL-level diagnosis

- **Evidence supplied:** historical snapshot reports 9 URLs and validation initiated 2026-11-14: three articles (`daily-typing-exercises-for-beginners`, `how-to-increase-typing-speed`, `touch-typing-vs-hunt-and-peck`) and `/disclaimer`, `/lessons`, `/privacy-policy`, `/scores`, `/themes`, `/typing-speed`. All these routes currently exist in source and are included in sitemap. Current GSC state is unknown.
- **Affected:** those nine paths on the preferred HTTPS WWW host.
- **Interpretation:** “Discovered” means Google knows a URL but had not indexed it in the snapshot; it does not identify a code error. Causes can include crawl scheduling, internal link prominence, perceived value, duplication, or other signals. Do not assume validation is still active/current.
- **Files:** see route inventory; article source `src/app/data/articles.js`; sitemap `src/app/sitemap.js`; shared navigation/components.
- **Fix:** obtain current URL Inspection details (last crawl, declared/Google canonical, crawl allowed, fetch status), verify HTTP 200/indexable rendered HTML and strong internal links, and assess page-specific usefulness. Correct only confirmed issues.
- **Complexity:** medium; content review varies by URL.
- **Verification:** GSC URL Inspection and Page Indexing after recrawl; compare sitemap status and Google-selected canonical.

### P2 — Search snippet for average typing speed has no observed clicks in the supplied sample

- **Evidence supplied:** query `average typing speed`: 120 impressions, 0 clicks in approximate 2026-09-23–2026-11-11 reporting. Average position and query landing URL were not supplied. `/typing-speed` and `/blog/average-typing-speed-by-age` cover adjacent but distinct intents.
- **Affected:** query and whichever URL GSC associates with it; likely candidates are not confirmed.
- **Why it matters:** without position, country/device and landing URL, it is not possible to distinguish snippet mismatch from low ranking or competing intent.
- **Files:** `src/app/typing-speed/page.js`, `src/app/data/articles.js`, homepage metadata/content.
- **Fix:** export query-page data with position, CTR, device and country. Inspect current snippets and competing SERP intent before tuning title/description or page content. Keep age-evidence intent distinct from general benchmark intent.
- **Complexity:** medium.
- **Verification:** compare GSC query/page CTR and impressions over a defined post-change window; no outcome is guaranteed.

### P3 — Structured data is present but needs rendered validation and scope discipline

- **Evidence:** homepage emits WebSite/WebApplication/FAQPage; blog list emits Blog with BlogPosting items; article and About pages emit JSON-LD. Structured data currently exists only where coded, and no central schema validation or WebPage/Breadcrumb coverage was found.
- **Affected:** `/`, `/blog`, `/blog/[slug]`, `/about`.
- **Why it matters:** JSON-LD must match visible page facts and be syntactically valid. Correct schema does not guarantee rich results. FAQ rich result display is restricted; do not add FAQ markup solely for a rich result.
- **Files:** `src/app/page.js`, `src/app/blog/page.js`, `src/app/blog/[slug]/page.js`, `src/app/about/page.js`.
- **Fix:** validate the actual rendered JSON-LD, dates, canonical URLs and visible text; add only accurate schemas supported by visible content. Do not invent author, rating, offer or review data.
- **Complexity:** low–medium.
- **Verification:** Schema.org validator and Google Rich Results Test on deployed canonical pages; manually compare data with visible content.

### P3 — Global third-party script and font loading deserve measurement

- **Evidence:** `layout.js` inserts AdSense script on every route; `globals.css` imports Google Fonts via CSS. No field CWV or consent setup was inspected.
- **Affected:** all routes, especially homepage and interactive pages.
- **Why it matters:** third-party execution/network/font loading can affect responsiveness, rendering and privacy requirements; impact is unknown without measurement.
- **Files:** `src/app/layout.js`, `src/app/globals.css`.
- **Fix:** measure before changing; if material, evaluate consent/conditional loading and self-hosted/Next font strategy without removing revenue or visual features blindly.
- **Complexity:** medium.
- **Verification:** Lighthouse/CrUX or RUM by device and page type; test ad behavior and layout shifts.

### P3 — No evidence of automated SEO integrity checks

- **Evidence:** package scripts include lint/build only; no test scripts or workflow/config found in tracked inventory. Article source is a plain array and sitemap trusts it.
- **Affected:** future route/article changes and all sitemap URLs.
- **Fix:** after the baseline audit, add lightweight checks for duplicate slugs, broken related slugs, missing title/description/canonical, future/invalid dates, and sitemap URL coverage/status. No new dependency required for basic source checks.
- **Complexity:** medium.
- **Verification:** run checks in CI and confirm an intentional invalid fixture fails.
